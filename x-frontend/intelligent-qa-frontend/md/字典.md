## 二、接口文档

| 属性 | 值 |
|---|---|
| **方法** | `GET` |
| **路径** | `/api/system/dict/{type}` |
| **参数类型** | Path 参数（非 query） |
| **认证** | 需要（由 axios 拦截器注入 `Authorization` header） |

### 支持的字典类型

| dictType | 中文说明 |
|---|---|
| `system_code` | 所属分系统 |
| `project_type` | 项目类型 |
| `resource_category` | 资源分类 |
| `publish_status` | 发布状态 |
| `file_type` | 文件类型 |
| `tag_type` | 标签类型 |

### 响应结构

```json
{
  "code": "200",
  "msg": "",
  "data": [
    { "code": "001", "name": "培训系统A" },
    { "code": "002", "name": "培训系统B" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `data[].code` | 字典编码，存储到数据库的值（即 `value`） |
| `data[].name` | 字典名称，展示给用户的文本（即 `label`） |

## 三、文件说明

### 3.1 `src/api/common.ts` — 接口层

```typescript
// 类型定义
interface DictItemVO { code: string; name: string }
interface SelectOption { label: string; value: string }

// 请求接口（路径参数）
getDict(type: string): Promise<DictItemVO[]>

// code/name → label/value 格式转换
dictToOptions(list: DictItemVO[]): SelectOption[]

// 根据 value 查找 label（用于表格展示）
getDictLabel(value: string, options: SelectOption[]): string
```

---

### 3.2 `src/store/modules/dict/index.ts` — 缓存层

```typescript
const dictStore = useDictStore()

// 首次调用请求接口，后续命中内存缓存，不重复请求
await dictStore.fetchDict('system_code')   // => SelectOption[]

// 清除单个字典缓存（如需强制刷新）
dictStore.clearDict('system_code')

// 清除所有字典缓存
dictStore.clearDict()
```

**缓存说明：**
- 缓存存储在 Pinia store 的 `dictCache` reactive 对象中
- 以 `dictType` 为 key，`SelectOption[]` 为 value
- 页面刷新后缓存清空，重新请求（如需持久化可配合 `pinia-plugin-persistedstate`）

---

### 3.3 `src/hooks/useDict.ts` — 组合式 API

#### 基础用法

```vue
<script setup lang="ts">
import { useDict } from '@/hooks/useDict'

// 获取单个字典
const { system_code } = useDict('system_code')
// system_code.value => SelectOption[]，组件挂载后自动填充
</script>

<template>
  <n-select
    v-model:value="form.systemCode"
    :options="system_code"
    label-field="label"
    value-field="value"
  />
</template>
```

#### 获取多个字典

```vue
<script setup lang="ts">
import { useDict } from '@/hooks/useDict'

const { system_code, project_type, publish_status } = useDict(
  'system_code',
  'project_type',
  'publish_status'
)
</script>
```

#### 表格展示字典名称

```vue
<script setup lang="ts">
import { useDict } from '@/hooks/useDict'

const { system_code, getDictLabel } = useDict('system_code')
</script>

<template>
  <!-- 表格列中展示名称而非编码 -->
  <span>{{ getDictLabel('system_code', row.systemCode) }}</span>
</template>
```

## 四、在 SubjectManagement 中的应用

```vue
<!-- src/views/SubjectManagement/index.vue → script -->
import { useDict } from '@/hooks/useDict'

// 加载 system_code 字典，直接绑定为 selectOption
const { system_code: selectOption } = useDict('system_code')
```

```vue
<!-- template 中搜索下拉、新建/编辑弹窗均绑定同一 selectOption -->
<n-select
  v-model:value="searchForm.type"
  :options="selectOption"
  label-field="label"
  value-field="value"
  clearable
  filterable
/>
```

**数据流：**
1. 组件 `onMounted` → `fetchDict('system_code')`
2. Store 缓存未命中 → 请求 `GET /api/system/dict/system_code`
3. 返回 `[{code, name}]` → `dictToOptions` 转为 `[{label, value}]`
4. 写入 Store 缓存 + 更新 `selectOption.value`
5. Naive UI `n-select` 响应式渲染选项

## 五、后期扩展

### 5.1 新增一个字典的使用步骤

1. 确认后端已有该 `dictType`（联系后端确认类型名称）
2. 在业务组件中直接调用 `useDict('new_type_name')`，**无需改动 API 层或 Store**

```typescript
const { new_type_name } = useDict('new_type_name')
```

### 5.2 强制刷新字典（如后台数据变更）

```typescript
import { useDictStore } from '@/store'

const dictStore = useDictStore()
// 清除指定字典的缓存，下次调用 useDict 时重新请求
dictStore.clearDict('system_code')
```

### 5.3 在非 setup 环境中使用

```typescript
import { useDictStore } from '@/store'

// 在 router guard、工具函数等场景中直接用 store
const dictStore = useDictStore()
const options = await dictStore.fetchDict('publish_status')
```

## 六、常见问题

**Q：下拉选项为空怎么排查？**
1. 打开浏览器 Network，检查 `/api/system/dict/system_code` 是否成功返回 `data`
2. 检查 `axios` 响应拦截是否正确解包 `data` 字段
3. 检查 `dictToOptions` 映射时字段名是否匹配（后端是否确实是 `code` / `name`）

**Q：多个组件同时使用同一字典会重复请求吗？**
不会。第一次请求完成后写入 Store 缓存，后续所有调用直接返回缓存数据。

**Q：页面刷新后需要重新请求吗？**
是的。当前是内存缓存，刷新后缓存清空，但由于 `onMounted` 会自动触发，不影响使用体验。
